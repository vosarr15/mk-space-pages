# mk-space-pages

本仓库用于归档和发布多个独立 HTML 页面。这些页面以静态文件形式存放，可通过 GitHub Pages 或其他静态托管服务直接访问。仓库内容不针对特定域名或网站，仅作为页面资源的管理与备份空间。

## 项目简介

`mk-space-pages` 是一个轻量级的页面归档仓库，主要用途包括：

- 存放独立编写的 HTML 页面（如工具页、展示页、说明页等）
- 通过版本管理保留页面历史记录
- 利用 GitHub Pages 功能实现静态页面发布
- 为多个不相关页面提供统一的存放位置

仓库本身不包含后端逻辑或动态内容，所有页面均为纯前端静态文件。

## 目录说明

```
mk-space-pages/
├── pages/          # 独立 HTML 页面存放目录
│   ├── page-a/     # 示例页面 A（可自行命名）
│   ├── page-b/     # 示例页面 B
│   └── ...
├── assets/         # 通用资源文件（CSS、JS、图片等）
├── index.html      # 仓库首页（可选，用于导航）
└── README.md       # 本文件
```

- `pages/`：每个子目录对应一个独立页面，包含其 HTML、样式和脚本。
- `assets/`：存放页面间可共享的静态资源，避免重复引用。
- `index.html`：仓库根目录下的首页，可用于展示页面列表或跳转链接（非必需）。

## 页面归档说明

每个归档页面应遵循以下规范：

- 页面文件放在 `pages/` 下独立子目录中，主文件命名为 `index.html`。
- 页面资源（CSS、JS、图片等）应尽量内聚在子目录内，减少跨目录依赖。
- 页面标题、描述等元信息在 HTML 中自行定义，不依赖外部配置。
- 页面应保持自包含，确保在静态托管环境中可正常渲染。

如需新增页面，只需在 `pages/` 下创建新目录并放入文件即可。仓库不会自动生成索引，建议在 `index.html` 中手动维护页面链接。

## 维护说明

- 本仓库以归档为主要目的，不计划频繁更新。页面内容稳定后即可提交。
- 建议每次新增或修改页面时，在 commit 信息中简要说明变更内容。
- 如有页面不再需要，可将其目录整体移除，同时更新 `index.html`（如存在）。
- 仓库不设置自动构建或部署流程，GitHub Pages 启用后，推送至默认分支即可生效。
